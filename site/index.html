COBALT

A small design system, and the loop that keeps its code honest against its own spec.

A personal exploration built to test a spec-driven component pipeline: a PRD written as a checklist, and a loop that implements it against deterministic gates instead of a human reading for drift. The pattern it's modeling is ordinary — a component that looks correct in isolation and quietly breaks the moment something changes everywhere at once: a rebrand, an accessibility pass, a dark mode rollout. Press the button below and this page's own theme system will show you a real instance of that: the focus ring's cobalt tone passes AA non-text contrast at 6.8:1 in light mode, but drops to 1.06:1 against the dark surface — invisible — so the dark theme has to swap the token to a lighter tint to stay accessible. That's not a hardcoded fix; it's the token itself changing per theme, which is the whole argument for why hardcoding is the failure mode this project is built to catch. The palette and form take Arne Jacobsen's AJ cutlery — the set that appeared in 2001: A Space Odyssey — as a reference point: what "futuristic" looked like in 1959 (brushed steel, tapered, no ornament) against what it looks like now.

The loop, actually running

This is a real, unedited transcript — node lib/loop.js demo/button-prd.md demo/button.css against a button deliberately built with a hardcoded color and no focus ring.

Auto-fixed All color values reference tokens; no raw hex or rgb raw hex color found → replaced with var(--color-accent)
Pass All spacing references the space scale; no bare px
Pass Every required state has a rule: default, hover, focus, active, disabled, loading
Blocked Visible focus ring using --color-focus, not the browser default outline no :focus-visible rule found at all — a design decision, not something to guess at
Pass Token contrast pairs meet WCAG AA
Pending Props match the API table exactly needs a real component file to introspect
Pending Renders in isolation with no console errors needs a real React component to mount

The loop fixed what was unambiguous, flagged what needed a real decision instead of guessing, and left the two gates that need real component code marked pending rather than faked. Reset and re-run yourself: ./demo/reset.sh && node lib/loop.js demo/button-prd.md demo/button.css
